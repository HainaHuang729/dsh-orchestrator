# 程序内静默等待

有现成程序调度能力、希望减少模型反复查询时使用。`scripts/wait-dsh.mjs` 只等待已派发的既存会话，不创建任务、不取消会话，也不自动启动其他模型。当前默认直接交付：外层程序收到新回复后保存交付、做文件存在等最低确认并转交用户，不接上 Codex 规划/审阅。历史 `run_low_poll.py` 的 Codex → DSH → Codex 链路用于对照试验，不是默认执行器；helper 本身不是完整 supervisor。

## 调用

派发本次 prompt **之前**记录该会话最新 `seq`，空会话用 `-1`；派发后，将原 `sessionId` 与这个基线交给 helper。一个等待期间该会话只允许本工作块的单个发话者；MCP 未暴露请求 ID，不能将并发 `queue`、`steer` 或其他发送者的回复可靠归到本次任务。

```text
node "<skill目录>/scripts/wait-dsh.mjs" <sessionId> --after-seq <派发前seq> --timeout-ms 1800000 --poll-ms 10000
```

脚本只用 Node 标准库，从本机 `~/.dsh/dsh-as-mcp/token` 读取认证，不打印令牌；CLI 仅连接本机 `http://127.0.0.1:8790/mcp`。程序内部默认每 10 秒查询状态，HTTP 单次上限默认 10 秒，可用 `--poll-ms`、`--request-timeout-ms` 调整；运行期间不逐次输出，退出时仅输出 JSON 摘要。

由父程序捕获最后 JSON 并按下表处理，父程序等待上限应长于 helper 的等待预算。`--timeout-ms` 是本次观察预算，不是 DSH 执行截止，也不意味着应取消任务。

| 返回与退出码 | 负责人动作 |
|---|---|
| `completed` / 0 | 连续两次 idle，且出现基线之后的新 user 及其后非空 assistant；仅代表收到本次新回复。做最低交付确认后原样转交，标记已交付/未独立验收，不自动追加审阅。 |
| `pending` / 2 | 保存会话身份及 `detail`，检查是否仍运行、需上下文或观察失败；继续跟进原任务，不按失败重派或宣称完成。 |
| `error` / 1 | 处理参数或启动错误（如令牌文件不可读）；核对原会话状态，不能据此假定 DSH 已停止。认证或网络观测错误也可能在 `pending.lastError` 中回传。 |

旧 assistant 回复不能证明本次完成；会话不在前 200 项、返回的最多 500 条消息中没有本次 prompt、观察异常或没有新助手消息时，helper 不宣称完成，最终可能返回 `pending`。消息窗口缺失须按实际 schema 核查，不能据此重派。idle 不证明后台子进程或外部请求已停止，取消与写入所有权规则照常适用。

DSH 也会把运行时上下文记录为 user 消息；helper 将任务标记绑定到基线之后最早的新 user，后续上下文注入不覆盖标记。运行 `node --test "<skill目录>/scripts/wait-dsh.test.mjs"` 可执行无网络的模拟测试。

程序静默等待减少模型轮询，不提供持久队列或自动唤醒。父任务跟进到直接交付，或按实际情况保存阻塞/中断记录；无法持续监督时采用 `SKILL.md` 的有界低频回退，不承诺退出 Codex 后自动回来接收结果。
